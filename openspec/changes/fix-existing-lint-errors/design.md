# Design

## Context

动机见 proposal.md。当前基线为 119 errors / 532 warnings：53 个分号错误、46 个未使用组件和 20 个其他错误。关系按钮直接修改 `item`，动画点赞还修改 `$parent.thread`；分页器修改 `meta.current_page`。帖子详情同时显示多个点赞和关注入口，因此局部复制状态会造成不同步。

## Goals / Non-Goals

**Goals:** 保持接口请求和 UI 结构，通过明确的组件事件让状态回到拥有数据的组件；消除全部 error 级问题，提供可复查的验证记录。

**Non-Goals:** 不清空 warning，不更换编辑器，不引入新的全局状态体系、第三方测试框架或依赖，不修改已配置的环境变量。

## Decisions

1. 关系按钮在请求成功后发出 `update:item`，传递包含已修改字段的新对象。包装按钮及用户卡片继续转发事件；页面或列表通过 `.sync` 更新自己拥有的对象。点赞计数和标记在同一次更新中提交，避免一次操作重复增减。保留现有 `after-toggle` 事件。相比按钮各自缓存状态，这种方式可同步帖子内多个入口，也避免把 prop 换个别名后继续修改。
2. 分页器只发出 `change`，显示的当前页继续以接口返回的 `meta` 为准。帖子与评论沿用已有回调；粉丝、关注页面接入 `change` 并向已有接口传递 `page`，解决原有按钮仅改变高亮的问题。
3. 通知中的 `v-html` 移到 `router-link` 内的原生元素，保留路由与内容。动态列表使用计算属性过滤无 subject 的记录；不改变加载更多条件。
4. 只应用 error 级自动修复，并删除未使用的组件注册和对应 import。余下语言错误采用局部修复：显式导入已有 Ace 依赖、移除无用绑定、使用 `Object.prototype.hasOwnProperty.call`、给 switch 分支独立作用域，以及去掉仅重新抛错的 try/catch。
5. 使用现有 Vue 编译工具和 Node 内置能力进行针对性回归检查，覆盖不修改输入对象、成功/失败事件、点赞计数和分页调用。浏览器验证使用当前本地服务；需要登录的写操作采用隔离的模拟响应，避免修改线上数据。

## Risks / Trade-offs

- [遗漏事件转发导致某个按钮不更新] → 搜索所有调用链，覆盖用户卡片、排行、节点、帖子和个人主页，验证同一对象多个入口。
- [替换对象覆盖异步期间的新数据] → 成功回调基于最新 prop 生成更新，保持无关字段，针对失败不发更新事件。
- [分页请求失败] → 不提前改写父级 metadata；仅在 API 成功后替换列表。
- [认证页面缺少真实账号] → 记录模拟交互结果与游客浏览器结果，明确区分真实认证验证。
- [现有模板含 HTML] → 本次仅调整渲染容器，沿用后端内容契约，不扩大为 HTML 清洗改造。

## Migration Plan

无需数据库或配置迁移。完成 lint、构建及回归检查后保留本地服务供复查；回退仅涉及本次源代码和 OpenSpec 文档变更。
